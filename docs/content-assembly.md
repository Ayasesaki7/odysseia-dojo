# Content assembly contract

The content assembly module is the seam between a public checkout and its
runtime content input. Its small interface is deliberately fixed:

```text
npm run content:fixtures
npm run content:local
```

Callers choose a mode, not paths. The module owns removal of current runtime
input, source validation, and materialization. That keeps fixture replacement,
the local allowlist, and Git-ignore behavior in one place instead of asking
build, CI, and preview callers to repeat security-sensitive filesystem logic.
The CLI accepts local mode only through the declared `npm run content:local`
command, so a public build or Preview command cannot disguise local assembly as
an implementation-script invocation.

## Tracked public source

Only these fixture roots are tracked as website content input:

```text
fixtures/src/content/docs/tutorials/
fixtures/src/content/docs/extensions/
fixtures/public/protected/tutorial-images/
fixtures/public/protected/attachments/
```

The module rejects additional top-level fixture roots and any fixture symlink.
This prevents a tracked fixture from becoming an indirect private-content link.

## Ignored runtime input

Both modes materialize only these ignored runtime paths:

```text
src/content/docs/tutorials/
src/content/docs/extensions/
public/protected/tutorial-images/
public/protected/attachments/
```

`content:fixtures` copies the public fixture corpus after deleting both runtime
roots, so it replaces stale local links or files every time.

`content:local` first verifies the trusted sibling private repository and then
creates directory links for those exact four roots. It never links the private
repository root itself. `archive/`, `question_banks/`, package files, tool
configuration, and `node_modules/` have no materialization path and cannot be
selected through either command.

The public project must be checked out as `dojo-sites/odysseia-dojo`; local mode
uses only its `../odysseia-dojo-content` sibling and refuses to run when `CI` is
set. Production materialization is a separate private workflow and is not an
interface in this repository.

## Content contract

`src/content.config.ts` extends Starlight's docs schema. Every document requires
non-empty `title` and `description`, `category` (`tutorial` or `extension`), a
non-negative integer `order`, a valid `updated` date, and boolean `isOutdated`.
`isOutdated` defaults to `false` but still rejects non-boolean values.

Runtime filenames can retain an ordering prefix such as `01-`. The content
loader removes that prefix from every URL segment and maps an `index` document to
its directory URL. For example,
`tutorials/01-discord-and-odysseia.md` becomes
`/docs/tutorials/discord-and-odysseia/`. Starlight's native autogenerated
sidebar uses the matching `sidebar.order` field; content keeps it equal to the
required `order` field.
